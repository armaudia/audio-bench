# B07 — Registry and local submission path

**Status: partial; metadata-only PR intake, catalog validation, and a constrained installed-SDK
synthetic smoke are implemented. Arbitrary provider execution remains blocked.**

- The closed registry keeps provider/model/implementation/engine/pipeline/host types distinct and
  rejects dangling references/cycles. `catalog` validates metadata without executing candidate code.
- `audio_bench smoke` now verifies the pinned SDK snapshot, runs only the two allowlisted installed
  SDK built-ins (`speex.ns.v0`, `dsp.highpass80.v0`) on the frozen synthetic suite, reconstructs
  outputs from source intervals, scores the full matrix, seals an immutable attempt and refuses to
  overwrite an existing destination.
- SDK build/config/provider/core identities are stored; the generated bundle is local and explicitly
  labelled synthetic/not qualified.
- `submissions/` manifests are checked against a closed schema on PRs. That job has read-only
  permissions and does not fetch or run the referenced source. Current central-runner policy only
  permits the pinned public `armaudia/audio-sdk` source and two built-in provider IDs.

```text
.venv/bin/python -m audio_bench catalog registry/catalog.json
  PASS: 5 entries; executed_candidate_code=false
.venv/bin/python -m audio_bench smoke --output .runs-local/sdk-smoke-highpass \
  --provider dsp.highpass80.v0
  PASS: 24 cases, 7 metrics/case, complete coverage
```

No arbitrary plugin, user-supplied executable/configuration, or untrusted submission is launched.
The documented audio-pro submitter-run manifest is disabled because its model execution rights
gate is still closed; it is not a benchmark result or evidence of private-runner ingestion.

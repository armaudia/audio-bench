# B05 — Paced runtime measurement

**Status: blocked/incomplete.** Exact schedule/accounting arithmetic and synchronous collector
diagnostics exist; the native collector does not yet implement the frozen paced schedule.

`src/audio_bench/pacer.py` tests frame-completion timing, first-valid-sample availability/deadline,
late labels, interval conservation, nearest-rank quantiles, integer/Fraction accounting and values
above 2^53. The sequential collector records monotonic receive time, elapsed wall time, worker and
collector CPU, RSS, accepted sample count and retained output/source maps. Those values are
functional diagnostics, not paced evidence.

Not implemented or tested in paced execution: absolute 10 ms scheduling, 15 ms collector/worker
stall injections, queue backpressure, zero/90% coverage fault injection, catch-up/late-delivery
classification, paced-vs-sequential waveform equivalence, warmup continuity, and per-workload
quality scoring. The synchronous send/receive loop has no bounded pending queue, so it cannot
establish the specified backpressure behavior. Official runtime claims remain unavailable without
the controlled isolated target and frozen criteria.

# B05 — Paced runtime measurement

**Status: partially implemented; B05 acceptance is incomplete.** The native collector has an
optional local paced path with continuous, frame-paced warmup followed by absolute monotonic
frame-completion deadlines. Warmup frames repeat an input segment, preserve provider state, and
precede the measured source interval. This is a local functional fixture, not the full workload
protocol or official runtime measurement.

`src/audio_bench/pacer.py` tests frame-completion timing, first-valid-sample availability/deadline,
late labels, interval conservation, nearest-rank quantiles, integer/Fraction accounting and values
above 2^53. Native `audio_bench_collect --paced` defaults to the planned 10-second warmup;
`--warmup-ms` accepts a 10 ms multiple from 0 to 600,000 for controlled tests. It schedules
measured frame k after its final sample at `t0 + (k+1)*10ms`. A dedicated sender schedules inputs while the collector receives outputs; the
sender holds at most three frames in flight. Per-frame JSONL records scheduled submit, send start,
OS-pipe admission, output receipt, in-flight count, send delay and lateness. This matches the
capture-time definition in `EVIDENCE_SPEC.md`; it does not claim an output-delivery deadline. A
synthetic integration test compares sequential and paced output bytes for the same input/config,
checks frame-completion boundaries, schedule spacing, the three-frame bound and accepted-sample
accounting. Collector resource fields now distinguish
direct-child and collector process CPU/RSS high-water marks; they do not claim process-tree totals.

Not implemented or tested: separately configurable send/receive queues, 15 ms
collector/worker stalls, saturation/backpressure fault injection, zero/90% coverage tests, catch-up burst
classification, workload/concurrency sweeps/refinement, repeated workloads, and workload-specific
quality scoring. The three-frame window does not establish fault behavior under load.
Official runtime claims remain unavailable without the controlled isolated target and frozen
criteria.

The collector summary's wall/CPU totals include warmup and reset overhead; they are not the B05
measurement denominators. A measured-only workload protocol must report those separately.

# B04 — Native SDK driver and trusted collector

**Status: implemented for local integration with the pinned installed SDK; not an untrusted
submission runner and not independently security-reviewed.**

## Implementation

- `native/CMakeLists.txt` uses only exported `AudioSDK::audio_sdk` and public headers. Configure
  verifies all 37 installed-prefix files, the exact archive hash and the copied manifest before
  consuming the package.
- `native/src/driver.cpp` runs the SDK session sequentially, carries state across a recording,
  accepts a final partial frame, explicitly drains, resets between recordings and closes only
  after DRAINED.
- `native/src/collect.cpp` is a separate supervisor. It owns request sequence numbers, launches a
  process group, uses bounded nonblocking pipes with poll timeouts, reads prevalidated float input,
  retains raw output/source maps, checks interval continuity, and records collector receive clocks,
  elapsed time, direct child CPU and collector CPU/RSS. It runs only the named built-in SDK fixtures
  in the demonstrated smoke; arbitrary submissions are not enabled.
- `native/src/wire.cpp` and `src/audio_bench/ipc.py` implement protocol v1. INPUT and SDK OUTPUT
  flags are distinct. Drain audio is OUTPUT/phase DRAIN; DRAINED is an acknowledgement. RESET and
  CLOSE are explicit. Golden vectors cover every message type.
- `native/tests/d256_regression.cpp` source-links an identity-delay fixture through the installed
  SDK facade. It asserts the expected D=256 second-frame interval
  `source_first_sample=-96`, `valid_offset=96`, `valid_count=64`. This snapshot passes the
  regression; no SDK defect is claimed.

or independent collector/security review exists. The implementation is restricted to the reviewed
installed SDK and synthetic fixture path.

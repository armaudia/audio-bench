# B11 — Durable automation and publication

**Status: local reconciliation groundwork, metadata-only PR validation, and static Pages deployment
are implemented; benchmark result automation/publication remains blocked.**

`src/audio_bench/reconcile.py` provides:

- conservative local impact tiers with manual review required;
- a file-locked local reconciliation event log;
- idempotent replay for an identical `(source, scope, sequence, request, core)` tuple;
- no advancement for incomplete or out-of-order evidence; and
- rejection of conflicting evidence at an already-used sequence.

The event/latest-snapshot records have closed schemas. `tests/unit/test_reconcile.py` checks
incomplete attempts, idempotency, advancement, out-of-order protection and conflicting sequence
rejection. These checks establish behavior for this local file implementation only, not durable
storage under machine loss, distributed concurrency or a remote append-only service.

```text
.venv/bin/python -m pytest tests/unit/test_reconcile.py -q
  PASS: 2 tests (also included in the final 72-test suite)
```

No remote ledger, target runner, dedicated machine lock, or result publisher was created. The PR
intake workflow validates JSON metadata only. The Pages workflow deploys a repository-owned static
shell whose result index currently has no entries. It does not publish benchmark bundles. B11
cannot be accepted until the manual B01–B09 path and B08 security gates are reviewed and external
infrastructure/retention/approval requirements are specified. This is not continuous benchmark
result publishing.

## Current implementation update

The repository now has a narrow publisher for validated synthetic smoke bundles: successful
main-branch CI emits two built-in provider summaries, and the Pages workflow merges them into
the public `benchmark-results` branch before deployment. This does not change the historical
local-ledger assessment above. Candidate-provider execution, private-runner execution tooling,
real corpus evidence, and production qualification remain unavailable. Submitter-owned JSON
result ingestion is now implemented as an unverified, no-source-access PR path.

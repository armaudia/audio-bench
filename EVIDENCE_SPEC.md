# Normative evidence specification, v0.1

Owner: audio-bench. Revision: 2026-11-13. Implement in B02 before official scoring. Runtime/provider semantics are owned by [SDK CONTRACTS.md](../audio-sdk/CONTRACTS.md); consume its released schemas rather than fork them. Artifact paths here describe files to implement.

## Encoding and identity

Control records are UTF-8 JSON, Draft 2020-12 schemas, closed objects, explicit required fields, no duplicate keys/BOM/lone surrogate/nonfinite values. JSONL is one canonical JSON object plus LF per line. Parse duplicate keys before JSON Schema validation; plain `json.loads` is insufficient. JSON Schema does not replace referential/interval/hash validation. No remote schema fetching while validating untrusted bundles; load a bundled allowlist of exact schema IDs/digests. Annotation-oriented `format` alone must not be relied on to enforce date/URL rules.

Use RFC 8785 canonical JSON bytes and SHA-256, represented `sha256:` plus 64 lowercase hex digits. Do not use the current `records.canonical()` as JCS: it uses ASCII-escaped sorted JSON and differs on Unicode and numeric serialization. Preserve that algorithm for old research records as `legacy-json-v1`; new IDs use the new explicit identity version, never reinterpret old hashes. Ingestion may accept human-formatted source JSON after strict parsing, validate it, and emit canonical bytes. Signed/hashed stored records and transported JSONL must already equal their canonical form. This resolves the earlier ambiguous demand to reject all noncanonical input while accepting editable manifests.

Identity numbers are safe integers only, range ±(2^53−1). Exact decimal settings have schema-declared string units and canonical decimal syntax; int64 sample/ns values and uint64 counters use canonical integer strings with explicit bounds. Metric values are finite IEEE-754 numbers or null with a reason. Never convert an absolute clock/sample index to float. Arrays retain order except declared sets (IDs sorted lexicographically). Hash digests are computed with each artifact's own ID field omitted; include schema_id and identity_algorithm=`jcs-sha256-v1`. Verification recomputes the same preimage. Runtime config identity is SDK-owned.

## Schemas and records to create

Large per-file lists are canonical JSONL shards (<=100 MB/file, <=1 MB/record) referenced by a compact control manifest, keeping each JSON control record <=1 MB. All required keys below are literal keys; details in parentheses define their types/constraints. Use `$defs` for bounded IDs, digests, integer strings and statuses. An optional key is absent; do not conflate absent with null. Schema version changes require a new schema_id. IDs are nonempty bounded ASCII; display text is bounded UTF-8. Reject unexpected keys, including inside nested objects. No generic metadata passthrough.

## Status, completeness and aggregation

Use execution statuses `passed`, `failed`, `blocked`, `invalid`, `not_applicable`, `not_run`. Reason codes are stable enums (asset_unavailable, rights_unknown, incompatible_contract, backend_failure, needs_reset, timing_mapping_unverified, incomplete_output, deadline_miss, harness_late, nonfinite_output, metric_undefined, invalid_bundle, cancelled, unsupported_capability); add schema-versioned metric-specific reasons such as zero_reference_energy/perfect_reconstruction. Required observations never disappear.

- `passed` means execution/validation completed. A mathematically undefined metric may be `passed`, value=null, reason=zero_reference_energy/perfect_reconstruction; finite-value summaries exclude it and show counts/reasons. It does not satisfy a qualification criterion requiring a finite quality statistic.
- `failed` means the declared behavior/criterion failed. `invalid` means malformed evidence/protocol. `blocked` means a named prerequisite unavailable. `not_applicable` requires suite-declared capability exclusion, never ad hoc masking of a failure. `not_run` is unexecuted planned work.
- Aggregate attempt status precedence is invalid > failed > blocked > not_run > passed. Declared not_applicable rows do not fail an otherwise complete applicable matrix. Missing rows are invalid, not not_applicable. A failed required metric prevents a passed attempt even when other values look good.
- Pairwise summaries use the same explicitly displayed intersection of finite paired observations and show excluded/missing/failed counts beside it. A headline full-cohort comparison requires no unexpected missing/failed cases; otherwise label it partial diagnostic and do not rank it as complete.
- Submission origin, source availability, maintenance, vendor endorsement, execution, reproduction, review and qualification remain independent fields. Same-company rerun is never independent reproduction. Commercial relationship never changes test eligibility/scoring.

## Core sealing without hash cycles

1. Freeze request/configuration/cohort/manifests/expected inventory before execution.
2. Store observations/outputs and summary, then create the artifact inventory for these payload files. Inventory excludes itself, `core.json`, attestations and reviews; its expected/actual sets cover only payload files and are closed.
3. Create the immutable run manifest with core_digest=null permanently (the external transport envelope may reference the sealed core); hash it. `core.json` references that digest plus inventory/payload digests. Compute core_digest with only its own core_digest field omitted, then write it once. Do not patch a hashed run manifest with its core digest afterwards.
4. Trusted collector attestation signs/references core digest outside the core. Review and qualification reference the sealed core/criteria outside its preimage. Signing keys are never accessible to candidate code.
5. Correction is a new core and new attempt when rerun, with predecessor_core_digest and reason. Keep old evidence. Export creates a separate sanitized public core; approval binds that digest. Private/public cores need not have equal IDs.

## Native measurement wire protocol

B04 implements a native driver plus a trusted native collector/supervisor. The SDK owns no benchmark executable. Python prepares inputs/config and launches the collector, then scores after measurement. The collector is a separate OS process outside the untrusted candidate sandbox; it owns run IDs, schedule, read/write pipe endpoints, actual receive clocks, host CPU accounting, status inventory and publication-neutral attestations. A plugin in the same process as a driver can tamper with driver timestamps: internal service/queue counters are explicitly candidate-reported diagnostics, never sole trusted proof of deadlines or qualification.

Use fixed binary framed IPC over inherited anonymous pipes/socket pairs. Header has 32-bit little-endian magic `0x41425530`, protocol version=1, message type, payload bytes, stream index and sequence; all counts bounded before allocation. Messages: PREPARE(config digest + bounded config), READY(build/descriptor digests), INPUT(epoch, first sample, valid count, 160 float32 samples), OUTPUT(epoch, source_first, valid_offset/count, 160 float32 samples, diagnostic service begin/end), END_INPUT(end sample), DRAINED, ERROR(status code). Maximum message 64 KiB. Reject duplicate/out-of-order sequence, bad length, NaN audio, wrong epoch or unrequested stream. A clean EOF without DRAINED is incomplete_output. Endianness/float format are explicit; source sample integers retain exact widths. Files and bundle paths are never chosen by these messages.

The collector preloads audio, spawns one driver per condition (all streams in that driver), waits for READY then schedules. Separate a pending IPC send from SDK admission: both accepted/rejected counters are recorded. A driver that stalls its reader cannot stall the collector's clock: use nonblocking IPC and bounded pending input, report IPC backpressure/rejection. Driver-side threads process state per stream under the selected SDK mode. Paired sequential rendering uses the same driver/config/input but no wall pacing. Collector receive time is observable output availability at this boundary, including IPC overhead. Hold transport/isolation constant across candidates; measure identity overhead as a separate control, do not silently subtract it.

## Timing and runtime equations

At 16 kHz, source sample n has capture time `t0 + n*62500 ns`, relative to the stream's first sample index. Frame k is complete and scheduled for submission at `t0+(k+1)*10000000 ns`. Never schedule at frame start while pretending all future samples are captured. Set t0 after warmup barrier; warmup is unscored but state is deliberately continuous for the runtime protocol. Score startup/drain in separate correctness tests.

Record scheduled/actual submit, enqueue/dequeue/service diagnostic clocks, collector output-receive time, scheduled/actual delivery, content/valid interval, queue depth, flags and denominators. Availability delay for a valid block is receive_ns minus capture time of its first valid source sample. Define deadline at capture time of that sample plus the frozen delivery budget. Partial-block scoring uses its actual valid start. Deadline miss occurs if availability/delivery is later than this deadline, even if recovered in a catch-up burst. Report first-sample and last-sample delay conventions explicitly; do not mix them.

Pacer lateness is actual_submit−scheduled_submit; capture scheduling and consumer delivery each have their own lateness. Use absolute monotonic deadlines and never shift t0 to hide an overrun. Use collector monotonic time for external measurements; another process/clock domain needs an explicit calibration and uncertainty. UTC is provenance only. Record negative/impossible delays as invalid evidence.

CPU occupancy = whole process-tree CPU seconds / actual monotonic wall seconds. Audio compute cost = process-tree CPU seconds / sum accepted valid source samples /16000 (apply parentheses: CPU/(samples/16000)). Throughput = accepted audio seconds / actual wall seconds. Record per-process and child totals and whether OS accounting includes all workers. Whole-host headroom uses idle/total CPU capacity across all logical CPUs over the same interval, distinct from one-core-normalized process occupancy. RSS reports current/max with OS semantics and byte units. No planned duration replaces actual elapsed denominators.

Clean completion requires accepted interval union equals delivered valid interval union plus explicitly declared edge exclusions/cancellations/failures. Rejections, concealment, duplicates and midstream missing intervals fail paced qualification even if accounted. Sequence count alone cannot prove waveform continuity: verify source maps and retained output fixtures. Every advertised loaded point retains actual output and proves equivalence to sequential output, or gets its own workload-bound quality scores.

## Metrics and frozen statistical protocol

Initial quality is STOI (`extended=false`) and ESTOI (`extended=true`), pystoi 0.4.1; zero-mean SI-SDR; SI-SDR improvement over raw; RMS gain ratio; clipping count (`abs(x)>1` before preview saturation) and max absolute sample. Use float64 calculations over identical valid intervals. Zero-mean SI-SDR: center s,y; alpha=dot(y,s)/dot(s,s); target=alpha*s; residual=y−target; 10*log10(sum(target²)/sum(residual²)). Zero reference/zero target/perfect residual have null/reason; no epsilon cap enters authoritative score. RMS output/input ratio has null reason for zero input. Store amplitude/gain diagnostics alongside SI-SDR.

For native-16k mirror audio use no resampling. If source conversion is necessary, freeze SciPy `resample_poly`, reduced integer up/down, window (`kaiser`, beta string `5`), padtype=`constant`, cval=`0`, float64 processing and final float32 cast. Clip/length conventions and resulting hashes are part of preprocessing identity; rate-converted source is a different manifest. No 16→48 kHz conversion is a fullband quality claim.

Freeze VoiceBank pairs and deterministic 24-case round-robin speaker selection before execution as specified in the older technical spec. Freeze the common interval map using verified candidate delays before scoring; a candidate unable to supply it fails. Do not alter the crop after seeing scores. The full report uses means/medians, per-case and per-speaker results and 10,000 paired utterance bootstrap draws within the observed speakers, NumPy PCG64 seed 20261111. Each replicate samples N_s utterances with replacement separately within each speaker, pools all resampled utterances with the original speaker counts, and computes paired mean deltas; 2.5/97.5 percentiles use NumPy linear quantile. Label inference conditional on those observed speakers. Runtime repeated streams are not independent speakers. A different corpus/grouping protocol gets a different cohort ID.

No arbitrary quality noninferiority margin is invented for a customer. B10 freezes the chosen primary metric, margin and direction before acceptance based on product requirements plus a baseline variability study. If unavailable, publish diagnostic quality and refuse a quality-qualified badge.
